# SMOKE.md — чек-лист ручной проверки перед релизом

Запускается перед каждым выпуском (`/prepare-release`). Каждый пункт — ~1 минута.
Провал любого пункта — стоп-релиз.

**Платформы 1.0.0:** прогонять на **Windows** и **macOS** (Apple Silicon).
Общие пункты ниже — на обеих ОС; блок [macOS](#macos-дополнительно-к-общим-пунктам)
— дополнительно на Mac. Keyring: Windows Credential Manager / macOS Keychain
(service `filar`). Пути данных и шорткаты — `docs/PLATFORM_NOTES.md`.

## Запуск

- [ ] Лаунчер стартует, все поля вкладок Models и SSH читаются из сохранённых настроек
- [ ] Запустить, закрыть, запустить снова — настройки на месте (в т.ч. API key из keyring)

## Агент и профили

- [ ] Локальный запуск: отправить запрос агенту → приходит ответ
- [ ] Профиль с некорректным ключом: понятная ошибка, **без секретов в тексте**
- [ ] Профиль с отсутствующим ключом: `no API key found`, имя профиля читаемо
- [ ] Два профиля LLM: запрос на первом, `Ctrl+L`, запрос на втором → оба отвечают

## SSH и транспорт

- [ ] `!ssh user@host` → подключение, `Ctrl+P` → ввод пароля → агент выполняет команду на удалёнке
- [ ] Настроить SSH-профиль в лаунчере → Launch → `config.toml` содержит `[[ssh_targets]]`
- [ ] Хост с `type = "agent"`: `ssh-add` ключа (в т.ч. с парольной фразой) → `./filar --target <host>` → подключение и команда; без агента (`unset SSH_AUTH_SOCK`) — ошибка `SSH agent unavailable` с подсказкой `ssh-add`. Windows: то же через службу OpenSSH Authentication Agent
- [ ] Хост с `type = "key"` и зашифрованным ключом: `./filar --target <host>` → запрос фразы без эха → неверная фраза → «Wrong passphrase, try again» → верная → предложение сохранить (`y`) → подключение; повторный запуск — без запроса. В TUI `Ctrl+O` на тот же хост без сохранённой фразы → маскированный ввод фразы. Фразы нет в логе
- [ ] `Ctrl+O` → оверлей выбора хоста → `↑↓` навигация → `Enter` → подключение → `Ctrl+T` на том же хосте; `Esc` → отмена
- [ ] Команда с подтверждением: диалог Approve/Deny, клик по кнопке, Enter = выбрать выделенную
- [ ] Деструктивная команда: подсвечена `danger`, требует подтверждения

## Интерактивный терминал

- [ ] `Ctrl+T` → открывается терминал → ввод работает → вывод появляется
- [ ] Прокрутка колесом / PgUp/PgDn в терминале → scrollback работает
- [ ] `Ctrl+T` повторно → возврат к агенту, терминал жив
- [ ] Unix/macOS: prompt соответствует `$SHELL` (на Mac обычно zsh); Windows: `cmd.exe`

## Вкладки

- [ ] `Ctrl+N` → новая вкладка, всегда local
- [ ] `Ctrl+Tab` / `Ctrl+1..9` → переключение без артефактов
- [ ] `Ctrl+W` → закрыть вкладку; последняя → выход
- [ ] Маркеры активности: `●` (работает), `?` (ждёт подтверждения), `○` (новый вывод)

## Интерфейс

- [ ] `F1` → оверлей справки открывается и прокручивается PgUp/PgDn
- [ ] `F2` → включить safe mode (Explain): статус-бар подсвечен, в ленте появляется путь к `.md`-файлу расшифровки
- [ ] В safe mode: команда приходит с пояснением и требует подтверждения; выполнить команду → файл содержит команду, пояснение, вывод
- [ ] `F2` повторно → safe mode выключен, статус-бар обычный
- [ ] Вставка из буфера (`Ctrl+V`) в поле ввода агента
- [ ] Мышь: скролл чата колесом, клик по `↓ N new` → пролистывание вниз
- [ ] Выделение мышью → копирование в буфер → тост `· copied`
- [ ] Команды сворачиваются/разворачиваются по клику
- [ ] Help-бар внизу показывает горячие клавиши текущего режима
- [ ] `Ctrl+L` циклит профили, статус-бар показывает токены

## Сессии

- [ ] Выход (`Ctrl+Q`) → сессия сохранена
- [ ] Повторный запуск с `--session <id>` → история чата, вкладки, ввод восстановлены
- [ ] История ввода агента (Up/Down) переживает перезапуск
- [ ] `F3` → оверлей выбора сессии: список сохранённых сессий, `↑↓` навигация, `Esc` — отмена
- [ ] `F3` → `Enter` на локальной сессии → история, профиль и ввод восстановлены в активной вкладке
- [ ] `F3` → SSH-сессия, хост которой совпадает с настроенной целью → подключение без запроса пароля (из keyring/env, как в лаунчере)
- [ ] `F3` → SSH-сессия без пароля в keyring или без совпадения с целью → запрос пароля → ввод → вкладка переключается на удалёнку
- [ ] Статус-бар показывает удалённый хост только после реального подключения (для восстановления SSH-сессии не «врёт» заранее)

## Kubernetes (3.0.0)

Нужен тестовый кластер `docker/k8s` с namespace `shop`, настроенный в
`[[kube_clusters]]`, и LLM-профиль. Проверка read-only: никаких изменений в
кластере не требуется и не допускается.

- [ ] Лаунчер → **+ Add cluster**: контексты прочитаны из kubeconfig без сети; **Check** показывает число подов в `shop`; Launch открывает кластер в TUI, `config.toml` и `pending_launch.json` содержат только путь к kubeconfig
- [ ] `filar --target <кластер>` открывает namespace по умолчанию; `filar --target <кластер>/shop` — сразу `shop`; Import/Export явно сообщают число пропущенных кластеров
- [ ] `Ctrl+O` → кластер → `shop`: статус-бар `⎈ <имя> › shop [prod]` (ASCII — `k8s:`), длинные имя/namespace сокращаются
- [ ] Если `namespaces` не задан, список приходит из API; `Esc` во время discovery отменяет ожидание, поздний результат не переоткрывает окно
- [ ] «Почему падает crashy?» → агент через `always` показывает подтверждения с инструментом, аргументами и целью `<кластер> / shop`; проверяет статус, события и previous logs и называет причину
- [ ] Вызовы API видны как сворачиваемые блоки `⎈ k8s_*` с таблицей/логом; ошибка RBAC или соединения понятна и не ломает вкладку
- [ ] `Ctrl+T`, `Ctrl+G`, `!cmd` → «во вкладке кластера нет шелла; войдите в под — 3.0.1», терминал/панели не открываются
- [ ] `Ctrl+Q` → повторный запуск → `F3` → сессия кластера: имя и namespace восстановлены, соединение установлено заново; в JSON нет kubeconfig и учётных данных

## Флот (2.0.0)

Нужны: группа `[[host_groups]]` по тегу и 3+ таргета с этим тегом; у одного
таргета нет учётных данных, один недоступен по сети.

- [ ] `Ctrl+O` → секция `groups — fleet` → группа → слой флота `[fleet: <группа> (N)]`, вступление называет хосты и выпавших `Skipped, no credentials: …`
- [ ] Вопрос флоту (напр. «какое ядро?») → **одно** подтверждение с радиусом `Runs on N hosts` (`l` — список) → сводка `X of N hosts answered, Y did not answer` в ленте, `no contact` и `skipped` названы
- [ ] Модели не уходит вывод хостов: в ленте — сводка и таблица различий, образцы ответов — только в боковой панели (`^J`)
- [ ] Команда записи (напр. `touch /tmp/x`) → отказ read-only политики **до** отправки на хосты, ни на одном хосте файла нет
- [ ] `Ctrl+Z` во время долгой команды → очередь не стартует, идущие прерываются, сводка с `cancelled` приходит
- [ ] Статус-бар во флоте: группа, `N/M live`, стоимость; на 80 колонках читается
- [ ] `Ctrl+O` во флоте → только хосты флота → хост открывается обычной вкладкой, флот остаётся
- [ ] `Ctrl+T`, `!cmd`, `Ctrl+P`, `F3` во флоте → понятный отказ с альтернативой, не молчание
- [ ] `Ctrl+S` во флоте → файл в `<save_dir>/<группа>/` с разделом `## Fleet` и строкой на **каждый** хост; рядом `*.runbook.md` — процедура для группы без имён/адресов хостов
- [ ] Выход и повторный запуск → `F3` → `fleet:<группа>` → флот с **сохранённым** составом (снять тег у хоста до восстановления — хост остаётся; удалить таргет из конфига — «No longer in the config, not asked: …»)
- [ ] `Ctrl+W` → флот закрыт, возврат на вкладку, с которой в него вошли

## Файловые панели (2.0.5)

Нужен SSH-таргет с сохранённым паролем (или ключом) и второй — без сохранённого
секрета; на хосте включена SFTP-подсистема (по умолчанию так).

- [ ] SSH-вкладка → `Ctrl+G` (и `Ctrl+П` на русской раскладке) → слева локальная машина, справа хост вкладки в его текущем каталоге; шелл вкладки после закрытия панелей работает (`!pwd`)
- [ ] Локальная вкладка → `Ctrl+G` → сразу выбор хоста для правой панели; хост с сохранённым секретом открывается без вопросов, без секрета — окно пароля, ввод звёздочками
- [ ] `Ctrl+O` в панелях → тот же оверлей, без групп флота; меняется только активная панель, хост вкладки (статус-бар) прежний
- [ ] Навигация: `Enter` в каталог, `Backspace` назад (курсор на покинутом каталоге), `r` обновляет
- [ ] Локально → хост: `Space` по файлу и каталогу → `F5` → подтверждение с «что и куда» → `Enter` → на хосте файл и каталог целиком, права файла сохранены
- [ ] Повтор того же копирования → вопрос «Replace?»; `o`, `s`, `a`, `n` работают; `Esc` отменяет копию
- [ ] Хост → локально (`c` вместо `F5`)
- [ ] Хост → хост (обе панели на разных хостах)
- [ ] Большой файл (сотни МБ) → видны процент и скорость → `Ctrl+Z` → «Copy cancelled», на цели нет ни файла, ни `*.filar-part`
- [ ] Копирование большого файла → `Esc` (панели закрыты) → `Ctrl+J` показывает `copy-N` с прогрессом → итог в ленте вкладки
- [ ] Хост из `[[host_groups]]` → панель с пометкой `[read-only]`, копирование на него отклоняется с объяснением, скачивание работает
- [ ] `F7` (и `m` / `ь`) → имя → папка создана локально и на хосте, курсор на ней; копирование в неё работает; существующее имя → «already exists»; имя с `/` → ошибка в окне
- [ ] Хост с выключенной SFTP-подсистемой → понятная ошибка в панели, без зависания
- [ ] Windows: в левой панели `Backspace` из `C:\` → список дисков → другой диск открывается; копирование на хост и с хоста работает в conhost и Windows Terminal

## Оценка безопасности команд (2.0.7)

Нужна секция `[risk_scorer]` (например `typesafe/jev-1.14` с ключом OpenRouter в
`FILAR_RISK_API_KEY`).

- [ ] Режим `always`: агент предлагает `ls` и `rm -rf /tmp/x` → окно открывается сразу с `Safety: rating…`, затем процент; у `rm -rf` заметно ниже и красный/жёлтый
- [ ] Approve → в ленте бейдж `[N%]` перед командой; Deny при высокой оценке и Approve при низкой работают как обычно
- [ ] Режим `never` (или allowlist для read-only): команда выполняется без ожидания, бейдж `[rating…]` сменяется процентом
- [ ] F1 → Usage → строка `Risk scorer: N ratings $…`
- [ ] Неверный ключ или адрес → `unavailable`, команды выполняются; нет ключа → при старте `Safety rating off: …`
- [ ] Без секции `[risk_scorer]` — ни строки в окне, ни бейджей
- [ ] Лаунчер: **Command safety score** → Decisions API, модель `typesafe/jev-1.14`, ключ → Launch → в TUI у команд агента есть оценки; в `config.toml` секция `[risk_scorer]` без ключа; повторный запуск лаунчера — настройки на месте, у ключа «saved»
- [ ] Лаунчер: снять галочку → Launch → оценок нет, секции `[risk_scorer]` в `config.toml` нет; **No key** → `key_env = ""`; пустая модель или адрес без `http` → ошибка, окно не закрывается

## macOS (дополнительно к общим пунктам)

Проверять в Terminal.app и/или iTerm2. Шорткаты — **Ctrl**, не ⌘ (см. `docs/PLATFORM_NOTES.md`).

- [ ] `F1` (при необходимости **Fn+F1**) → оверлей справки открывается
- [ ] `Ctrl+T` → интерактивный терминал ↔ агент; локальный PTY показывает привычный prompt (`zsh` при `$SHELL=/bin/zsh`)
- [ ] `Ctrl+V` → вставка из буфера в поле ввода агента
- [ ] `Ctrl+Q` → выход, сессия сохранена
- [ ] В help-оверлее видна пометка, что шорткаты на Ctrl, не ⌘
- [ ] `Ctrl+G` → файловые панели; копирование клавишей `c` (F5 на Mac — через Fn)
