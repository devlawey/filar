# Filar — Пользовательская инструкция

> Терминал с AI-агентом поверх SSH. Агент выполняет команды на локальной или
> удалённой машине, запрашивая подтверждение перед каждой операцией.

---

## 1. Быстрый старт

### 1.1. Запуск (основной способ)

1. Скачайте релизный бинарник или соберите из исходников (`cargo build --release`):
   - **Windows:** `filar.exe`
   - **macOS (Apple Silicon):** `filar-*-macos-aarch64` → `chmod +x` и при
     необходимости `xattr -d com.apple.quarantine …` (см. `docs/PLATFORM_NOTES.md`)
2. Запустите бинарник (двойной клик или из терминала)
3. Откроется GUI-лаунчер — введите модель, URL и API-ключ прямо в интерфейсе
4. Нажмите **Launch**

API-ключ сохранится в системном хранилище учётных данных автоматически —
**Windows Credential Manager** или **macOS Keychain** (service `filar`).
При следующем запуске поле уже будет заполнено. Пароли SSH сохраняются, если
отметить «Save password» для соответствующего SSH-профиля (ключ
`ssh_target:{alias|SSHn}`).

### 1.2. Запуск из терминала

```bash
# Windows (PowerShell) или macOS (Terminal / iTerm2)
filar          # Windows: filar.exe
```

Без аргументов — всегда открывается GUI-лаунчер.

### 1.3. CLI-режим (напрямую в TUI, без GUI)

CLI-режим читает `config.toml` (см. раздел 2). Нужны env-переменные для ключей.

```bash
# Локальная машина (требуется GLM_API_KEY в env)
export GLM_API_KEY="ваш-ключ"          # macOS / bash / zsh
# $env:GLM_API_KEY = "ваш-ключ"        # Windows PowerShell
filar --target local

# SSH-таргет + конкретный LLM-профиль
filar --target test-docker --llm glm

# Восстановить предыдущую сессию
filar --target local --session 1718900000
```

### 1.4. Сборка из исходников

```bash
git clone https://github.com/devlawey/filar.git
cd filar
cargo build --release
```

| Платформа | Бинарник |
|-----------|----------|
| Windows | `target\release\filar.exe` |
| macOS | `target/release/filar` |

**1.0.0** официально поддерживает Windows и macOS; Linux — не цель релиза
(пути данных через XDG уже есть в движке).

## 2. Конфигурация

У filar три места хранения настроек. Обычному пользователю ничего знать
о них не нужно — GUI-лаунчер всё делает автоматически. Этот раздел — для
тех, кто запускает через CLI или хочет вручную настроить профили.

### 2.1. Как это работает (обзор)

| Файл | Где | Кто пишет | Зачем |
|------|-----|-----------|-------|
| `settings.json` | `{OS data dir}/filar/` | GUI-лаунчер | Сохраняет состояние UI (SSH-профили, модель, URL, выбор) |
| `pending_launch.json` | `{OS data dir}/filar/` | GUI-лаунчер → TUI | Транзитный: передаёт настройки запуска от GUI к TUI, удаляется после чтения |
| `config.toml` | `{OS data dir}/filar/` | GUI-лаунчер (частично) + пользователь | Фолбэк для CLI-режима; полный набор настроек |
| OS Credential Manager / Keychain | Системное хранилище | GUI / TUI | API-ключи и SSH-пароли — **только здесь**, нигде в файлах |

Пути `{OS data dir}/filar/`:
- Windows: `%APPDATA%\filar\`
- macOS: `~/Library/Application Support/filar/`
- Linux: `~/.local/share/filar/` (или `$XDG_DATA_HOME/filar/`; не цель 1.0.0)

**Поток при запуске через GUI:**
1. Пользователь редактирует поля в лаунчере → сохраняются в `settings.json`
2. Нажатие «Launch» → пишется `pending_launch.json` + обновляется `[llm]` в `config.toml`
3. GUI запускает TUI-подпроцесс
4. TUI читает `pending_launch.json`, удаляет его, использует настройки оттуда

**Поток при запуске через CLI (без GUI):**
1. `pending_launch.json` не существует → TUI читает `config.toml`
2. Ключи берутся из env-переменных (или Credential Manager, если ранее сохранялись)

### 2.2. config.toml — справочник

```toml
# ── Режим подтверждения команд ─────────────────────────────
confirm_mode = "allowlist"
#   always    — каждая команда требует явного approve/deny
#   allowlist — read-only (ls, cat, ps...) выполняются автоматически; остальные — с подтверждением (по умолчанию)
#   never     — все команды без подтверждения (опасно!)
#   explain   — safe mode: агент обязан пояснить каждую команду и ждать подтверждения.
#               Сессия автоматически пишется в Markdown. Переключается клавишей F2.
#               (!command — shell escape — не затрагивается, работает как обычно.)

# ── LLM по умолчанию (профиль "default") ──────────────────
[llm]
model = "glm-5.1"
api_base_url = "https://open.bigmodel.cn/api/paas/v4"
max_tokens = 4096
# temperature = 0.3          # опционально (0.0–2.0)
# top_p = 0.9               # опционально (0.0–1.0]
# [llm.extra_body]           # опционально, произвольные поля в тело запроса
# thinking = { type = "disabled" }

# ── Дополнительные LLM-профили ─────────────────────────────
# Каждый профиль может использовать другую модель/провайдера.
# Ключи хранятся в Credential Manager под именем из key_env.
[[llm_profiles]]
name = "deepseek"
model = "deepseek-chat"
api_base_url = "https://api.deepseek.com/v1"
max_tokens = 8192
key_env = "DEEPSEEK_API_KEY"

# ── Таймауты (в секундах) ──────────────────────────────────
[timeouts]
command_secs = 300   # выполнение одной команды
llm_secs = 60        # один вызов LLM API
connect_secs = 15    # установка SSH-соединения

# Долгие jobs (pull/download/build): используйте инструменты
# start_background_job / background_job_status / cancel_background_job —
# не делайте `sleep N` под command_secs; для live-прогресса — Ctrl+T.

# ── SSH-таргеты ───────────────────────────────────────────
# Лаунчер синхронизирует свои SSH-профили в эту секцию при каждом Launch.
# Можно также добавлять таргеты вручную — лаунчер сохранит чужие записи.
[[ssh_targets]]
name = "my-server"
host = "192.168.1.100"
port = 22
user = "admin"

[ssh_targets.auth]
type = "agent"        # agent | key | password
# path = "~/.ssh/id_ed25519"  # только для type = "key"
# password = "..."            # только для type = "password" (лучше SSH_PASSWORD env)

# ── Директория сохранения расшифровок ─────────────────────
# Куда Ctrl+S и авто-расшифровка (Explain mode) пишут .md файлы.
# Не задано = текущая рабочая директория.
# save_dir = "C:\\Users\\me\\Documents\\filar-transcripts"
```

### 2.3. Режимы подтверждения

| Режим | Поведение |
|-------|----------|
| `always` | Каждая команда требует явного approve/deny |
| `allowlist` | Read-only (ls, cat, ps...) выполняются автоматически; остальные — с подтверждением (по умолчанию) |
| `never` | Все команды без подтверждения (опасно!) |
| `explain` | Safe mode: агент обязан пояснить каждую команду и ждать подтверждения. Сессия пишется в Markdown. Переключается F2 на лету. |

### 2.4. API-ключи и пароли

**В GUI-режиме:** ввести ключ прямо в интерфейсе. Сохраняется в OS credential
store автоматически при первом Launch:

| Платформа | Хранилище | Service / ключи |
|-----------|-----------|-----------------|
| Windows | Credential Manager | service `filar` |
| macOS | Keychain | service `filar`; SSH — `ssh_target:{alias\|SSHn}` |

**В CLI-режиме:** через переменные окружения:

```bash
export GLM_API_KEY="ваш-ключ"          # профиль по умолчанию
export DEEPSEEK_API_KEY="ваш-ключ"    # именованный профиль
export SSH_PASSWORD="пароль-ssh"     # SSH auth type = "password"
# Windows PowerShell: $env:GLM_API_KEY = "…"
```

Ключи **никогда** не записываются в `config.toml`, `settings.json`, или
`pending_launch.json`.

### 2.5. Где искать config.toml

Поиск в порядке приоритета:
1. `FILAR_CONFIG` env (явный путь)
2. `./config.toml` (текущая директория)
3. `{OS data dir}/filar/config.toml` (сюда пишет лаунчер; см. §2.1)
4. `config.toml` рядом с исполняемым файлом (`filar.exe` / `filar`)

Если ни одного файла нет — используются встроенные значения по умолчанию.

## 3. GUI-лаунчер

При запуске без аргументов открывается окно "Filar — Launcher":

```text
┌──────────────────────────────────────────┐
│  Filar                                    │
│  Terminal with an AI agent over SSH       │
│──────────────────────────────────────────│
│  Recent sessions:                         │
│    + Start new session                    │
│    2025-06-20 14:30 | local | Помог…      │
│    2025-06-19 10:15 | my-server | …       │
│──────────────────────────────────────────│
│  Target:              [local        ▼]   │
│  LLM profile (preset): [default    ▼]    │
│  Model:               [glm-5.1        ]   │
│  API base URL:        [https://open.big… ]│
│  API key:             [··············]    │
│──────────────────────────────────────────│
│          [Launch]  [Cancel]              │
└──────────────────────────────────────────┘
```

- **Recent sessions** — список до 10 последних сессий (клик восстанавливает)
- **Target** — `local` или SSH-таргет из конфига
- **LLM profile (preset)** — пресет из конфига; при выборе автозаполняет поля Model и URL
- **Model** — имя модели (можно править вручную)
- **API base URL** — адрес API (можно править вручную)
- **API key** — ваш ключ к LLM API (вводится прямо в интерфейсе)
- **Launch** — запускает TUI с выбранными параметрами

## 4. TUI — Режим агента

Основной режим работы. Вы пишете задачу на естественном языке, агент
выполняет команды и возвращает результат.

### 4.1. Горячие клавиши

Все шорткаты с модификатором используют **Ctrl** (Control), не ⌘ Command —
так на Windows, Linux и macOS. На macOS клавиша F1 часто требует **Fn+F1**
(см. `docs/PLATFORM_NOTES.md` → macOS shortcuts).

| Клавиша | Действие |
|---------|----------|
| `F1` | Оверлей справки (все горячие клавиши, по секциям); на macOS — часто Fn+F1 |
| `F2` | Переключить safe mode (Explain): агент обосновывает каждую команду, сессия пишется в Markdown автоматически |
| `Enter` | Отправить сообщение / Подтвердить выбранную кнопку |
| `Ctrl+Q` | Выход (в Confirming — сначала отклоняет) |
| `Ctrl+Z` | Отмена: прервать агента (Thinking) / отклонить команду (Confirming) |
| `Ctrl+C` | Ничего (оставлен под копирование выделения) |
| `Ctrl+T` | Переключение между агентом и терминалом |
| `Ctrl+Tab` / `Ctrl+Shift+Tab` | Переключение вкладок |
| `Ctrl+N` | Новая вкладка (всегда local) |
| `Ctrl+W` | Закрыть вкладку (последняя → выход) |
| `Ctrl+L` | Сменить LLM-профиль для текущей вкладки |
| `Ctrl+O` | Оверлей выбора хоста (local + [[ssh_targets]]) |
| `Ctrl+V` | Вставка из буфера обмена |
| `Ctrl+P` | Ввод пароля (маскированный) |
| `Up/Down` | Навигация по истории ввода (переживает перезапуск) |
| `!command` | Shell escape (прямой вызов команды) |
| `a` / `y` | Подтвердить команду |
| `d` / `n` | Отклонить команду |
| `Tab` | Переключение Approve/Deny в диалоге |

### 4.2. Управление мышью

| Действие        | Результат                                  |
|-----------------|--------------------------------------------|
| Колесо вверх/вниз | Прокрутка истории чата (по 3 строки)    |
| Клик по `▾`/`▸` | Развернуть/свернуть вывод команды          |
| Клик по заголовку команды | Развернуть/свернуть вывод        |
| Клик по `↓ N new` | Прокрутка к последним сообщениям         |
| Drag (зажать ЛКМ и тянуть) | Выделение текста и копирование в буфер |
| Двойной клик    | Выделение слова                            |
| Тройной клик    | Выделение строки                           |

В режиме подтверждения команды:
- Клик по кнопке **Approve** / **Deny** — выбирает действие
- `Enter` активирует выделенную кнопку (по умолчанию — **Deny**)

В интерактивном терминале (Ctrl+T):
- Колесо — скролл истории терминала (или стрелки в less/man)
- Клик/перетаскивание — проброс мыши в приложение (vim, htop, mc)

### 4.3. Режимы приложения

- **Normal** (поле ввода) — ввод текста, отправка агенту
- **Thinking** (агент работает) — ожидание ответа LLM / выполнения команд
- **Confirming** (подтверждение) — агент просит разрешение на команду
- **Interactive** (терминал) — обычный эмулятор терминала

### 4.4. Блоки чата

Каждое сообщение отображается цветным блоком:

| Цвет     | Тип       | Описание                              |
|----------|-----------|---------------------------------------|
| Cyan     | User      | Ваше сообщение                        |
| Green    | Agent     | Ответ/рассуждение агента              |
| Yellow   | Command   | Команда + вывод + статус (✓/✗)       |
| Red      | Error     | Сообщение об ошибке                   |
| Gray     | System    | Системное уведомление                 |

### 4.5. Подтверждение команд

Когда агент предлагает выполнить команду, вы видите:

```
⚠ COMMAND CONFIRMATION REQUIRED
Agent wants to run:  sudo apt update
Explanation:         Updating package lists to check available versions
⚠ WARNING: This command may modify system state

[a]pprove  /  [d]eny
```

- Нажмите `a` или `y` — команда выполняется
- Нажмите `d` или `n` — команда отклоняется, агент продолжит работу
- `Ctrl+Z` — отклонить команду (без выхода)
- `Ctrl+Q` — отклонить команду и выйти из приложения

## 5. TUI — Интерактивный терминал

Нажмите `Ctrl+T` в режиме агента для переключения в обычный терминал.

```
┌──────────────────────────────────────────┐
│ INTERACTIVE                    local     │ ← статус-бар
│──────────────────────────────────────────│
│ user@machine:~$ ls                       │
│ Documents  Downloads  Music  Pictures    │
│ user@machine:~$ _                        │ ← курсор
│──────────────────────────────────────────│
│ Ctrl+T=Agent mode │ (terminal input is forwarded) │ ← help-бар
└──────────────────────────────────────────┘
```

- Работает локальный PTY (команды выполняются на вашей машине)
- **Шелл:** на Unix/macOS — `$SHELL` (обычно `zsh` на Mac), иначе `sh`;
  на Windows — `cmd.exe`. Команды агента по-прежнему идут через отдельный
  non-interactive executor (`sh -c` / PowerShell) и не зависят от этого PTY
- Полная поддержка ANSI: `vim`, `htop`, `less`, `top` и т.д.
- Ресайз окна автоматически меняет размер терминала
- `Ctrl+T` — вернуться в режим агента (терминал остаётся живым в фоне)
- При выходе из шелла (exit/EOF) — автоматический возврат в режим агента
- **С 0.6.0:** у каждой вкладки свой терминал. Запустили долгую команду —
  переключились на другую вкладку `Ctrl+Tab`, вернулись — всё на месте.
  Закрытие вкладки `Ctrl+W` закрывает её терминал.
- Ярлыки вкладок показывают маркеры активности: `●` — агент работает,
  `?` — ожидает подтверждения, `○` — новый вывод в фоновой вкладке

## 6. Сессии

### 6.1. Автосохранение

Каждая сессия **автоматически сохраняется** при выходе из TUI (Ctrl+Q или
закрытие терминала).

Сохраняется:
- ID сессии (Unix timestamp)
- Timestamp (дата и время)
- Имя таргета (local / SSH-таргет)
- Имя LLM-профиля
- Все сообщения чата (включая вывод команд)

### 6.2. Хранилище

- **Windows:** `%APPDATA%\filar\sessions\`
- **macOS:** `~/Library/Application Support/filar/sessions/`
- **Linux:** `~/.local/share/filar/sessions/`

Формат: JSON-файлы (`<id>.json`). Хранится не более **10 последних** сессий
(старые удаляются автоматически).

### 6.3. Восстановление

**Через GUI:** кликнуть на сессию в списке "Recent sessions" → Launch.

**Через CLI:**
```powershell
filar.exe --target local --session 1718900000
```

При восстановлении загружается вся история чата. В начале добавляется
системное сообщение: "Session restored — history loaded from disk".

## 7. Логи

Пока TUI активен, логи **не пишутся в терминал** (иначе строки лога легли бы
поверх интерфейса). Вместо этого весь лог идёт в файл, а сообщения уровня
**WARN и ERROR дополнительно дублируются в чат** как системные строки
(например, `filar_transport::ssh: reader: channel closed` при разрыве SSH).

### 7.1. Где лежит файл

- **Windows:** `%APPDATA%\filar\logs\filar.log`
- **macOS:** `~/Library/Application Support/filar/logs/filar.log`
- **Linux:** `~/.local/share/filar/logs/filar.log`

Файл ротируется посуточно (`filar.log.YYYY-MM-DD`). В нём — полная запись
с временными метками, включая уровни ниже WARN.

### 7.2. Уровень логирования

Уровень берётся из переменной окружения `RUST_LOG` (по умолчанию `info`).
Чтобы поднять детализацию:

```powershell
$env:RUST_LOG = "debug"
filar.exe
```

Можно фильтровать по модулю, например только транспорт:
`$env:RUST_LOG = "filar_transport=debug,info"`.

## 8. CLI-аргументы

```
Usage: filar [--target <name>] [--llm <profile>] [--session <id>]

Options:
  --target <name>   Подключиться к таргету ('local' или имя SSH-таргета из конфига)
  --llm <profile>   Использовать LLM-профиль ('default' или имя из [[llm_profiles]])
  --session <id>    Восстановить сессию по ID
  -h, --help        Показать справку
```

Без аргументов → GUI-лаунчер.

### Примеры

```powershell
# Локальная работа, LLM по умолчанию
filar --target local

# SSH на сервер, DeepSeek
filar --target my-server --llm deepseek

# Восстановить сессию на локальной машине
filar --target local --session 1718900000

# Только GUI (без аргументов)
filar
```

## 9. Типичный сценарий работы

### Сценарий 1: Диагностика через агента

1. Запустите: `filar --target my-server`
2. Введите: "Найди, какой процесс слушает порт 8080, и покажи его рабочую директорию"
3. Агент предложит: `sudo lsof -i :8080` → подтвердите (a)
4. Агент предложит: `ls -la /proc/<pid>/cwd` → подтвердите (a)
5. Агент выдаст итоговый ответ с путём

### Сценарий 2: Быстрый фикс через терминал

1. Запустите: `filar --target local`
2. Нажмите `Ctrl+T` — переключитесь в терминал
3. Выполните нужные команды вручную
4. Нажмите `Ctrl+T` — вернитесь к агенту
5. Спросите агента: "Проверь, что сервис nginx запущен"

### Сценарий 3: Восстановление вчерашней сессии

1. Запустите без аргументов: `filar`
2. В GUI выберите вчерашнюю сессию из списка
3. Нажмите Launch — история загрузится
4. Продолжите диалог: "А теперь проверь логи за сегодня"

## 10. Решение проблем

### "failed to load config"
- Filar работает и без `config.toml` — используются значения по умолчанию
- Для CLI-режима создайте `{OS data dir}/filar/config.toml` (см. раздел 2)
- Или укажите путь: `$env:FILAR_CONFIG = "C:\path\to\config.toml"`

### "API key is required"
- В GUI-режиме: введите ключ в поле "API key" и нажмите Launch
- В CLI-режиме: установите переменную `$env:GLM_API_KEY = "ваш-ключ"`

### "SSH target 'xxx' not found"
- Проверьте имя таргета в `config.toml` (поле `name` в `[[ssh_targets]]`)
- Список доступных таргетов смотрите в `config.toml` в секциях `[[ssh_targets]]`

### SSH-подключение не удаётся
- **Пароль:** установите `$env:SSH_PASSWORD`
- **Ключ:** проверьте путь в `config.toml` → `[ssh_targets.auth]` → `path`
- **Порт:** проверьте поле `port` (по умолчанию 22)

### TUI отображается некорректно
- Убедитесь, что терминал поддерживает ANSI (Windows Terminal, PowerShell 7)
- Минимальный размер окна: ~80×24

### Сессии не сохраняются
- Проверьте права на запись в `{OS data dir}/filar/sessions/`
- Создайте директорию вручную при необходимости

## 11. Безопасность

- **Ключи API** вводятся в GUI или через env-переменные, никогда не хранятся в config.toml
- **Режим `allowlist`** (по умолчанию): read-only команды выполняются автоматически,
  остальные требуют подтверждения
- **Режим `explain`** (safe mode, F2): агент обязан пояснить каждую команду,
  сессия пишется в Markdown автоматически
- **Деструктивные команды** (rm -rf, mkfs, dd...) помечаются предупреждением ⚠
- **Zero-install:** на удалённой машине не создаётся никаких файлов —
  команды выполняются в существующем шелле через SSH-канал
